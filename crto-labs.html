01 / Active Directory

Rechercher les machines et paramètres du domaine Active Directory

Objectif : inventorier les machines, stratégies de groupe et relations d'approbation, puis examiner la cartographie dans BloodHound.

Trouver les ordinateurs du domaine Active Directory

ldapsearch (samAccountType=805306369) --attributes name,dnsHostName,operatingSystem

Le filtre sélectionne les objets ordinateurs. Les attributs retournent leur nom, leur nom DNS et leur système d'exploitation déclaré.

Trouver les stratégies de groupe (GPO) du domaine

ldapsearch (&(objectClass=groupPolicyContainer)) --attributes displayName,gPCFileSysPath

Recherche les objets de stratégie de groupe et leurs chemins de fichiers.

Identifier les domaines liés par une relation de confiance

ldapsearch (objectClass=trustedDomain) --attributes trustPartner,trustDirection,trustAttributes,flatName

Affiche le domaine partenaire, le sens et les propriétés de l'approbation.

Afficher toutes les GPO dans BloodHound

MATCH (n:GPO) RETURN n

Attention : une requête LDAP vide peut provenir du contexte Kerberos ou des droits de la session, pas forcément d'un domaine vide.

Adapté de Discovery Lab · botesjuan.

02 / Windows

Contrôler les restrictions AppLocker sur Windows

Objectif : identifier le mode PowerShell, examiner les règles effectives et les autorisations des dossiers d'un poste de laboratoire.

Savoir si PowerShell est en mode restreint

$ExecutionContext.SessionState.LanguageMode

Le résultat peut indiquer ConstrainedLanguage. Cela ne suffit pas à décrire toute la politique AppLocker.

Voir les règles AppLocker réellement appliquées

$policy = Get-AppLockerPolicy -Effective
$policy.RuleCollections

Affiche les collections de règles applicables dans le contexte de la machine.

Vérifier les droits d'accès aux dossiers Windows

icacls C:\Windows\Tasks
icacls C:\Windows\Temp

Vérifie les listes de contrôle d'accès ; ne suppose pas qu'un dossier est accessible en écriture.

Adapté de AppLocker Challenge · botesjuan. Cette fiche couvre le diagnostic de configuration.

03 / Infrastructure Red Team

Vérifier la configuration du laboratoire Cobalt Strike

Objectif : comprendre les composants d'une simulation Red Team : serveur d'équipe, client, profils, listeners et extensions.

Consulter les journaux du serveur Cobalt Strike

sudo docker logs cobaltstrike-cs-1

Affiche les journaux du conteneur nommé dans le laboratoire source. Adapte son nom à ton environnement.

Identifier les points d'écoute Cobalt Strike

Pour chaque listener, relève son nom, son protocole, son port, son interface d'écoute et les règles réseau associées. Ne réutilise pas les identifiants ou mots de passe d'un autre environnement.

Adapté de Cobalt Strike Primer · botesjuan.
